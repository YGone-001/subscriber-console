## Design Specificity Verdict

**LLM assessment：中高特异性。** IMSI、PLMN、OCS 配额、Gy/Ro 会话、孤儿 reservation、资费覆盖、审批和审计证据让内容明显属于 xCloud。Dashboard 的行动项、readiness、耗尽时间和健康矩阵开始接近“电信运营舰桥”。但外壳仍是通用企业后台的顶部栏、侧栏、workspace tabs、breadcrumbs、卡片与表格组合；新建订阅用户也仍像字段集合，而不是 xCloud 特有的“身份 → 影响 → 风险 → 审批/验证”受控变更流。

**Deterministic scan：** `detect.mjs --json src` 扫描 210 个文件，exit 0，返回 `[]`。原审计的 side-tab、bounce-easing、layout-transition、grid-background 共 35 条已全部清零，没有确认到误报。

**Visual overlays：** 可变注入预检和 `detect.js` 注入均成功，隔离的 `[Human]` 浏览器标签中存在 overlay/instrumentation DOM；没有输出可靠的 `impeccable` console finding，与 CLI 的 0 条一致。会话已按协议关闭，因此 overlay 未被保留。

## Overall Impression

xCloud 已从“真实电信 IA + 松散 UI 契约”进化为一套更稳定、主题一致且移动端可用的专业控制台。最大机会不再是修外观，而是把“状态真相”和“受控变更”做成产品的核心交互：任何高风险动作都应明确当前对象、影响、风险、权限、恢复和验证结果。

## What's Working

1. **运营语义真实。** Dashboard 能把配额耗尽、流量集中、会话和孤儿 reservation 转成行动项，而不是只展示图表。
2. **移动数据视图已脱离桌面压缩模型。** 390px 下无页面级横向溢出，密集表格转换为带字段标签的记录卡，移动壳层和主要顶部动作达到 44px。
3. **专家效率和视觉系统成型。** 命令面板、快捷键、批量操作、语义状态 token、明暗主题和 reduced-motion 契约均有真实实现。

## Priority Issues

### P1 — 高风险 Dialog/Drawer 契约仍不统一

- **为什么重要：** 新建订阅用户、角色、审批、OCS 和确认反馈涉及身份、认证、计费与权限；缺少焦点约束、Escape、背景 inert 和关闭后焦点恢复，会让键盘与辅助技术用户失去上下文。
- **证据：** 新建用户弹层没有完整 `role=dialog`/`aria-modal`；生产实测按 Escape 后 `.users-drawer-layer` 仍存在。多个自制弹层未复用 `Dialog`/`useDialogFocus`。
- **修复：** 所有模态反馈、确认和抽屉统一走共享 Dialog primitive；补齐名称、描述、焦点约束、Escape、背景 inert 和焦点恢复。新建用户按任务阶段渐进披露，提交前显示影响摘要。
- **建议命令：** `$impeccable harden`

### P1 — 运营状态口径互相冲突

- **为什么重要：** NOC 用户必须相信“现在是否需要行动”；P1 行动项、active alerts、anomalies、degraded 和 idle 并存会直接破坏控制台可信度。
- **修复：** 定义 alert、recommendation、anomaly、degraded 的层级和归属；Dashboard 只呈现一个权威健康结论，并允许展开查看组成与更新时间。
- **建议命令：** `$impeccable clarify`

### P1 — 审批中心先暴露查询器，后暴露任务

- **为什么重要：** 4 个 workflow tabs、12 个 action type、6 个状态、4 个风险等级和日期字段同时出现；空状态又没有清除筛选，审批人很难迅速回答“现在要决定什么”。
- **修复：** 默认聚焦“待我审批”；把高级筛选移入二级面板；空状态展示活动筛选摘要、清除筛选和推荐视图。
- **建议命令：** `$impeccable distill`

### P2 — 移动首屏仍被状态块和工具占据

- **为什么重要：** 订阅页四个全宽状态块和多个操作把核心记录推到较下方；OCS 部分筛选、刷新和分页控件实测仅 36–43px。
- **修复：** 指标改为紧凑 2×2 或横向状态条；把移动 OCS 工具统一纳入 44px coarse-pointer 规则。
- **建议命令：** `$impeccable adapt`

## Cognitive Load

总体为高负担，8 项约 5 项失败：单一焦点、一次一件事、最少选择、工作记忆、渐进披露。Dashboard 同屏竞争项过多；新建订阅用户的六大配置域实际同时展开；命令面板和审批过滤器一次提供远超 4 个决策选项。信息分组、标题层级和移动字段标签是明显优点。

## Emotional Journey

- 登录页克制、安静，建立专业感。
- Dashboard 的 P1 行动项、耗尽时间和会话语义形成第一次信任高点。
- 状态口径冲突形成最严重信任低谷。
- 新建用户弹层在高风险时刻突然暴露几十个字段，缺少影响和验证预览。
- 审批空状态解释了“没有数据”，但没有提供恢复动作，结束感偏弱。

## Persona Red Flags

**Alex（专家用户）：** Ctrl+K、Ctrl+B、批量操作和排序有效；但命令面板约 18 项且未自动聚焦搜索，新建用户缺少模板、差异预览和专家快速路径。

**Sam（键盘/辅助技术用户）：** 新建用户和多个自制 Drawer 缺完整 dialog 契约；生产实测用户抽屉按 Escape 不关闭。共享命令面板是正确对照：能自动聚焦并按 Escape 关闭。

**Casey（分心的移动用户）：** 记录卡无横向溢出且字段标签保留；状态块把记录推离首屏，部分 OCS 控件低于 44px，新建用户长表单也没有可见草稿/中断恢复承诺。

## Minor Observations

- 浅色 `--text-muted: #61777e` 在常见背景上的对比度为 4.10–4.35:1，小字号不满足 WCAG AA。
- 中文模式仍有 OCS/Rating/错误反馈硬编码英文。
- 浏览器标题仍为 “4G Core Subscriber Management”，未体现 xCloud 产品身份。
- Dashboard 的 Recharts 和 5 秒轮询可进一步按可见性与首屏优先级优化。

## Questions to Consider

- xCloud 的唯一权威“当前态势”究竟是什么，其他推荐、告警和异常怎样从它展开？
- 新建订阅用户能否从“配置字段集合”改成“受控变更作业”，并在提交前给出影响、审批和恢复摘要？
- Workspace tabs 和 breadcrumbs 哪一个真正服务持续值守，另一个是否可以降级为辅助信息？
