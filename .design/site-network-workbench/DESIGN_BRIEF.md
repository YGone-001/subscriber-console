# Design Brief: 站点／网络分组工作台

日期：2026-11-10。状态：待开发的设计方案，不是当前运行事实。

用户已确认：首版包含站点创建、编辑、退役及主机与站点归属调整；Agent 归属仍由管理员在现有 Agent 页面维护。

配套文档：[开发计划](DEVELOPMENT_PLAN.md)、[实施任务](TASKS.md)。源码核对基线：`9069d21dc6ef276ce9870aa0be138f62520dc3d2`。

## Problem

值班人员目前需要在网元、Agent、告警、配置快照和报表之间反复查找同一批资源。增加第二台主机或另一个运营网络以后，很难连续回答：这个站点有哪些主机和网元、采集是否及时、哪些告警仍未关闭、哪些配置出现变化、哪些资源尚未明确归属。

主要使用者是维护 EPC、5GC、IMS 和 charging 资源的操作员。管理员同时负责采集节点访问和 Agent 归属；查看员需要完整的只读浏览。首版服务于当前单主机管理，并为后续多主机、多运营网络提供明确的管理上下文。

## Solution

在现有资产工作台增加“站点／网络”视图。用户先选择站点或逻辑网络，再在同一范围内查看资源、Agent、告警和配置证据，最后进入既有详情页处理问题。具有配置权限的用户可以维护站点和显式资源归属；界面始终说明每种关联来自哪一个权威来源。

网络在首版是按显式 `networkKey` 声明生成的逻辑视图。站点和主机继续使用 Inventory 的资源 UUID，组织包含关系继续使用 Topology 的 `contains` 边。共享站点可出现在多个网络视图中，界面不把网络强行解释成站点唯一的物理父级。

成功标准：从入口选择一个站点后，首屏能够明确范围、资源规模、Agent 时效和待处理问题；任何缺失、部分覆盖或归属冲突都有可追溯的解释。筛选后的数字、列表、报表和导出使用同一范围规则。

## Experience Principles

1. **先确定范围，再阅读状态**：网络、站点和过滤条件在 URL 与上下文条中保持可见，局部数据不会冒充全局统计。
2. **每条关联可追溯**：资源声明、Topology 包含关系、Agent 管理归属分别标注来源，发生冲突时保留双方证据。
3. **按任务展开细节**：概览负责发现问题，分页明细负责核查，维护表单负责单项变更，避免首屏同时堆叠多张完整列表。

## Aesthetic Direction

- **Philosophy**：延续 xCloud 现有紧凑型运维工作台，以稳定的信息层级和清晰的证据状态组织页面。
- **Tone**：平静、准确，异常明确，正常内容保持克制。
- **Reference points**：现有 Inventory 主从布局、Agent 节点证据、NF Health 和配置快照的状态表达；借鉴 CNMS 站点分组的浏览方式。
- **Anti-references**：不引入独立大屏、地图演示、重复侧边栏入口、装饰性网络连线；不复制 CNMS 按进程名关联网元的站点模型。

## Existing Patterns

- Typography：复用自托管 Noto Sans SC 与现有 `--font-interface` / `--font-data`；UUID、PLMN 和时间使用既有数据字体规则。
- Colors：使用 `styles/globals.css` 的语义色和 `styles/tokens.css` 的兼容映射；不新增硬编码颜色，青绿用于主要交互，状态色保持原语义。
- Spacing：延续 4px 基线、紧凑表头、既有面板圆角和响应式断点。
- Components：复用 `OperationsPageFrame`、`InventoryViewSwitch`、`MetricStrip`、`CursorPagination`、`StatePanel`、`Dialog`、`Field` 和 `OperationFeedback`。
- Runtime：React/Vite + SWR，经既有同源 API 客户端读取 Go；不新增认证运行时或 UI 库。
- Localization：所有新增用户文案同时维护中英文 locale，技术标识 `PLMN`、`networkKey` 和 UUID 不翻译成新的身份概念。

## Information Architecture

建议新增一个规范 SPA 路由：`/inventory/groups`，作为 `InventoryViewSwitch` 的第四个视图。“网元 / 资产 / 本机观测”保持现有入口和默认行为。共享运维导航仍归属于 Inventory，不再增加侧边栏一级菜单。

页面从上到下为既有运维页框、范围与完整性上下文条、单一筛选工具条、主体工作区。主体采用左侧分组目录和右侧所选范围面板。

```text
资产工作台                   [网元] [资产] [本机观测] [站点／网络]
运维导航                     使用已有共享导航与单一刷新入口
当前范围 / 数据覆盖 / 读取时间 / 归属问题
运营商名称 / PLMN / 域 / 搜索 / 重置

分组目录                     当前范围面板
[按站点] [按网络]            主机 | Agent | 逻辑网元与实例 | 未关闭告警
站点或网络列表               概览 / 资源 / Agent / 告警 / 配置 / 归属检查
  显式关联的站点或主机       当前页签的一个主要工作区
未归属 / 归属问题            分页、证据说明、相应维护入口
```

“按站点”展示 Inventory 站点及已声明的包含层级；“按网络”展示显式网络分组及其关联站点。相同站点在不同网络下仍是同一个 UUID。目录先分页加载分组，展开节点再取有界成员，不为每个节点预取健康与告警。

| 区域 | 内容与默认行为 |
| --- | --- |
| 范围条 | 网络键、所选站点、可选主机、运营商名称、PLMN；支持逐项清除，持续显示当前范围 |
| 核心指标 | 主机数、Agent 总数及在线数、逻辑 NF 与 NF 实例数、未关闭告警数；每项附来源与覆盖状态 |
| 概览 | 监测覆盖、待处理问题摘要、配置证据覆盖；不重复其他页签的完整资源表 |
| 资源 | 在主机、逻辑 NF、NF 实例间切换；身份、生命周期、关联状态、测量时效分别展示 |
| Agent | 节点状态、服务器接收时间、显式站点／主机绑定、主机测量；管理员可进入原管理页 |
| 告警 | 当前未关闭队列；明确包含 active、acknowledged、assigned、recovering；关闭历史通过报表查看 |
| 配置 | 已绑定当前范围资源的配置来源、最近尝试／成功时间、基线和变化状态；显示本地采集覆盖限制 |
| 归属检查 | 缺失声明、重复归属、跨来源冲突、失效引用、图读取受限；提供对应维护入口 |

“未归属”是待补充管理信息，不表示资源故障。只有在相应范围解析完整且确认没有关系时，才标为未归属；读取失败或超限时标为待解析。已确认的共享关系单列为共享，不与冲突混为一谈。

## Key Interactions

1. **选择范围**：切换站点／网络模式，选择目录节点。服务端解析范围后再显示相应指标与明细；切换范围清除旧分页和旧行选择，迟到响应不得覆盖新范围。
2. **精确筛选**：站点、网络、主机、运营商名称、PLMN 与域按约定求交集。PLMN 保留前导零及五／六位原字符串。无匹配时显示有效的空范围，不退回全平台。
3. **核查证据**：点击指标进入同范围对应页签；查看单条数据的来源、接收／测量时间和归属依据。失败分区可单独重试，其他分区仍可阅读。
4. **维护站点**：具有 `core.configure` 的用户创建、编辑或退役站点。创建时显式提交 `kind=site`，默认建议生命周期为 planned；站点地址不作为主机身份。退役显示关联影响，不级联删除主机、网元、Agent 或历史证据。
5. **维护资源归属**：逐资源编辑显式网络声明，使用原 Inventory CAS 接口。站点关联一个网络，不会自动给所有子资源写入同一网络声明；未声明的子资源有独立提示和维护入口。
6. **调整包含关系**：选定规范站点和主机 UUID，新增 `contains` 或退役已有边。既有接口没有原子“迁站”，界面分别展示两个动作及结果；部分成功时重新读取并呈现实际关系，禁止显示整体迁移成功。
7. **查看明细**：Inventory 详情使用合法的 Inventory `returnTo` 恢复工作台 URL；跨实体详情采用明示的新标签页链接，保留原工作台。Agent／告警／配置详情继续遵守各自 `returnTo` 白名单，不放宽通用返回地址限制。
8. **生成报表**：传递已支持的分组选择器和绝对时间窗，明确“按当前归属筛选历史证据”。没有实现分组过滤的入口不发送伪参数、不显示为范围内报表。

## Responsive Behavior

- 宽度 ≥1280px：左右双栏，目录宽度有上限，右侧表格为主工作区，避免过宽指标卡占用首屏。
- 981–1279px：收窄目录，筛选允许换行，低优先级列移入详情。
- ≤980px：目录改为按钮打开的可关闭面板；选择后回到主内容。六个页签可在局部横向滚动，页面本体不产生水平溢出。
- 窄屏表格保留身份、状态和时间，其他字段通过详情查看；维护表单成为单列。
- 验收覆盖 1920×1080 的 80%／100% 浏览器缩放、1366×768、390px 窄屏及键盘 200% 缩放下的重排，不用单一截图代表全部适配。

## Accessibility Requirements

- 普通文字对比度至少 4.5:1，大文字及交互边界至少 3:1；状态同时有文字和图标，不仅依赖颜色。
- 目录优先使用语义化嵌套列表和展开按钮；只有实现完整键盘协议时才采用 `role=tree`。
- 筛选、页签、分页、维护按钮均可用键盘操作并有可见焦点；完整性变化通过克制的 `aria-live` 通知。
- 对话框使用既有焦点约束，关闭后回到触发按钮；错误定位至相关字段，未保存表单提供离开提醒。
- viewer 不渲染可提交的维护控件，后端仍独立拒绝写入；禁用控件说明原因。

## Out of Scope

- 信令追踪、MML、远程命令、自动重启／修复、任意脚本任务。
- 漫游协议、漫游关系推断、运营商账号隔离、多租户权限或新的认证模型。
- 独立的站点／网络数据库、复制 Inventory 节点、复制 CNMS 的站点集合与进程名绑定。
- 自动扫描／导入站点、按 IP／主机名／进程名推断归属、自动给子资源继承网络身份。
- 通过 Agent 协议下发归属或采集远程配置／日志；本期不修改 Agent 报告协议。
- 全国地图、地理坐标、容量规划、历史站点归属重建、站点 SLA／可用率或跨站点因果分析。
- 本次计划编制不包含业务代码实现、运行服务切换或生产数据修改。
