## 2. 参考实现核查结论

CNMS 的 `backend/internal/handler/ue_info.go` 通过 HSS 的 `impi`、`impi_impu`、`impu` 补充 SIP URI；其 `frontend/src/pages/UEInfo.tsx` 以 `sip_uri` 是否存在显示注册状态。这不能证明当前注册，首版不沿用该判断，也不沿用逐 UE 查询和 IMSI 前缀 LIKE 关联。

CNMS 的 `backend/internal/handler/business_metrics.go` 查询 S-CSCF 的 `contact`、`impu_contact`、`impu`，统计未过期的不同 Contact ID。它的单位是 Contact 绑定，不能直接称作用户数、私有身份数或物理终端数。该 SQL 仅是来源候选，尚未证明与当前部署 schema 和状态字段等价。

Kamailio 官方文档说明，`ims_usrloc_scscf` 可仅使用内存，或按定时器写回数据库。因此数据库读取成功只证明这次读取成功，不能单独证明数据库与运行时同步。[官方数据库模式说明](https://www.kamailio.org/docs/modules/stable/modules/ims_usrloc_scscf.html)

`ims_registrar_scscf` 提供 REGISTER 处理及独立的注册 Contact／IMPU 统计，支持将两种计数分开设计；文档不证明当前 xCloud 二进制的版本和可用接口。[官方模块文档](https://www.kamailio.org/docs/modules/stable/modules/ims_registrar_scscf.html)

## 3. 数据源资格核验先行

在冻结实际 SQL 和状态判断前，完成下列核验并留下脱敏记录：

| 项目 | 必须确认的事实 | 未确认时的行为 |
|---|---|---|
| S-CSCF 版本与来源 | 部署组件、schema 版本、实例／共享库边界、来源原生主键 | 适配器报告 unsupported_schema，不猜表结构 |
| 持久化模式 | 是否只存内存、写回方式、同步周期及可验证的延迟证据 | 不宣称当前运行时注册；内存模式不以空库判离线 |
| 绑定有效性 | Contact 状态枚举、注销／延迟删除、永久绑定和到期值的含义 | 原始证据保持未知，不仅凭 expires 判已注册 |
| 时间 | expires 类型、数据库时区、数据库时钟与注册证据时间 | 新鲜度 unknown，不使用浏览器时钟补判 |
| 身份关联 | HSS 的显式关联键和唯一性；IMPI 是否确有 IMSI 映射 | 不从 SIP URI、号码或字符串前缀猜 IMSI |
| 只读能力 | 受限账号／视图、固定 SELECT、连接预算及传输配置 | 来源关闭，不复用 CNMS 默认高权限连接配置 |

首个候选是经核验的 S-CSCF MySQL 绑定读取器；HSS 只作可选身份补充。若真实环境只有内存数据，本次先完成只读运行时接口的可行性说明，再单独冻结固定读取接口；不临时改成 shell、通用 RPC 或更改网元持久化配置。

部署人员在环境中提供连接配置和账号，不在计划、测试日志或聊天中保存真实连接凭据。当前未读取现场数据库、未建立授权、未变更配置。

## 4. 观测模型与计数

每条证据必须带 `sourceId`、来源资源 UUID、原生身份键、证据类型、`readAt`、可选 `sourceAsOf`、有效期与可用性。数据库证据明确标记为数据库观测；同步滞后未知时，`sourceAsOf` 和新鲜度不由 `readAt` 冒充。

模型保持三个独立维度：

| 维度 | 建议状态／字段 | 语义 |
|---|---|---|
| 来源读取 | ok / not_configured / invalid_config / unavailable / unsupported_schema | 能否读取此来源 |
| 覆盖与新鲜度 | complete / partial / unavailable；fresh / stale / unknown | 是否完整、能否证明证据足够新 |
| 身份绑定证据 | active_binding_observed / no_active_binding_observed / unknown | 观测到有效绑定、完整读取下未见有效绑定、证据不足 |

`no_active_binding_observed` 不等于已证明注销、注册失败或设备离线。部分读取、来源失败、无法验证的同步状态以及来源未覆盖该身份时，不能建立当前未注册结论。数据库中仍有效的记录可以作为数据库绑定证据展示，但不能自动升级为端到端在线或 IMS 服务健康。

- 有效绑定数：按来源内原生 Contact 身份去重，多个 IMPU 关联同一 Contact 不重复计数。
- 含有效绑定的公开身份数：按已核验的身份语义去重；多个 Contact 属于同一 IMPU 时只计一次。
- 私有身份／签约身份数量：HSS 可选、独立计数，不作上述两个计数的同义词或注册成功率分母。
- 不同来源和不同运营网络默认不去重为一个人；相同 URI 可属于不同管理权威。共享库不得重复声明成独立可相加的人口。
- 缺失映射、有效期和统计字段返回 null 或显式状态，不补零。
- 来源部分失败时，全范围精确总数为 null，另给出已观测数量和缺失来源；分页当前行数不能冒充总数。
- 首版不把新计数填进旧 `imsOnlineUsers`／`totalIMSUsers` 字段。运维总览使用带明确单位的新摘要；旧字段保持兼容，不更换含义。

## 5. 来源配置、归属与读取边界

采用部署拥有的来源清单和凭据引用，声明稳定 `sourceId`、适配器类型、名称、S-CSCF 资源 UUID、身份权威和可选 HSS 来源。路径、主机和库名按实际环境配置，既有 `/etc/xCloud/gcc/NE` 只是网元配置目录，不作为注册状态接口。

建议最多 16 个来源，初始不自动扫描、不自动启用。配置解析失败不会阻止既有 EPC/5GC UE 功能工作。每个连接池具有明确超时、最大连接数与关闭路径；远程数据库校验证书，回环／本机连接另作环境配置。

按 [既有分组规则](../../docs/architecture/site-network-workbench.md) 解析源资源 UUID 的 network/site/host/operator/PLMN 交集。不从 URI realm、IMSI 前缀、IP、名称或 Agent 元数据推导归属，不从站点继承 NF 网络声明。空范围保持空，不回退全局。

分组含义是“选中组织范围内的 IMS 来源所报告的注册绑定”，不证明 UE 的物理所在地、归属运营商或漫游访问网络。共享 S-CSCF 仍按来源声明表达，不能把整台共享来源的人口称为本站点本地用户。

Go 仍为唯一 API owner。读取器使用固定、参数化的有界查询和字段白名单；不读取认证密钥、认证向量、完整订阅 XML、SIP 报文或任意 SQL。HSS 补充采用批量读取，不做逐行 N+1。检查执行计划但不在 GET、启动或本任务中创建外部数据库索引。

首版不新增 Mongo 业务写或注册历史集合；沿用基础限流等既有基础设施副作用。来源配置暂不新增网页 CRUD。

## 6. 建议 API 和前端集成

新增只读 API 的建议集合为：

```text
GET /api/ims/registrations
GET /api/ims/registrations/summary
```

来源状态随列表和摘要返回，首版不单独增加来源管理 API。最终字段、分页策略和错误码在数据源资格核验后冻结，当前不修改注册计数或契约清单。

建议筛选包括 sourceId、q、state，以及既有 networkKey/siteResourceId/hostResourceId/operatorName/plmn。IMSI／MSISDN 关联搜索只在具有显式、经验证的映射时开放；没有映射时保留 IMPU 搜索，不通过猜测补齐。客户端不得指定数据库地址、表名、列名或 SQL。

列表默认 50、最多 200 条身份；搜索上限 128 字符。游标绑定来源、筛选、分组版本和适配器版本，采用确定排序，过期／上下文冲突要求重新开始；不承诺跨数据库事务快照。完整计数与列表分别提供观测时间，明确最终一致性。

建议初始预算：全请求 8 秒、单次来源查询 2 秒、并发来源最多 4；单响应总量最多 10 MiB，展开的绑定记录最多 2000 条。超时、超界和下游取消均显式降为部分／不可用。数据源核验须证明分页与查询成本满足边界；扩大预算需要实测依据。

API 使用现有 cookie 会话、`core.read`、每用户端点 120/60 秒限流和 `Cache-Control: no-store`。admin/operator/viewer 按既有读权限进入。日志脱敏搜索和身份参数，不记录数据库密码、DSN、原始 SQL 错误或原始 Contact 内容。

前端遵循 [设计说明](DESIGN_BRIEF.md)：复用 UE 工作区页框、单一刷新、SWR 和 URL 状态，增加 IMS 视图与详情抽屉；从分组页跳转时保留范围和返回上下文。运维总览复用新摘要服务，不反向依赖 EPC/5GC 来源必须已配置。

## 8. 验收矩阵

开发验收必须覆盖：

- SIP URI 存在而没有有效 Contact，不能显示已注册；多个 IMPU 共用 Contact、多 Contact 共用 IMPU、相同 URI 不同权威分开计数。
- 到期边界、时区、空／特殊 expires、状态枚举、延迟删除、内存模式、写回延迟和读成功但证据新鲜度未知。
- 来源无配置、无权限、断连、超时、未知 schema、部分失败、空交集和超过行／体积上限；失败不补零，旧缓存不冒充当前证据。
- HSS 缺失、歧义关系、恶意搜索、通配符和批量上限；只投影批准字段，无身份猜测和 N+1。
- core.read 权限、未登录／会话撤销、参数校验、限流及日志／响应脱敏；不存在注册控制或外部数据库写路径。
- 分页后计数不变成当前页数量；筛选、来源和分组变化拒绝复用游标；最终一致性不被称为事务快照。
- 专属临时 MySQL 实例的真实 SQL 集成验证；只使用明确由验收拥有的实例／库，不在生产库建表、写 fixture 或自动建索引。
- 前端针对来源／分组切换竞态、抽屉返回、语言／主题、错误／空／部分状态、窄屏和实际缩放进行浏览器验证。
- Go 测试／竞态检查、前端完整检查、相关 contract、API owner、文档与 AGENTS/CLAUDE parity 门禁；按实际新增集合更新计数。

现场验收另行完成：只读账号及实际源验证，由现场人员使用真实 UE 正常注册、续期、注销，核对运行时与数据库证据及时间差；记录多来源覆盖。开发测试、合成数据和官方文档都不能替代这项证明。

## 9. 交付与后续边界

后端和 UI 分开提交，保留既有 API、构造器和未配置时的 EPC/5GC 行为。实现完成后更新当前架构／操作文档及必要 AGENTS/CLAUDE 内容，再按仓库规则将已完成计划移出 HEAD、保留 Git 历史。

本轮只编制计划，不操作现场数据库、来源账号、网元配置或业务服务。后续部署、sudo、服务与生产进程操作由环境拥有者执行；开发阶段可以先完成隔离验证，但没有真实来源时不能宣布真实注册观测已可用。

远端 Agent 采集、只读运行时接口、历史趋势和 IMS 日报均为独立后续范围，不用空实现预先占位。
