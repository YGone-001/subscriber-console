## 1. 已确认范围与交付目标

用户确认：首版汇总现有采集证据并检查新鲜度，不触发新采集。

目标流程：创建并预览范围 → 保存／启用计划 → 到时生成固定执行记录 → 查看问题和证据缺口 → 进入现有工作台处理 → 下次巡检观察变化。支持手动立即巡检，统一经过持久化队列和执行器。

本模块只新增 Ops 计划、调度状态和执行结果。对 Inventory、Topology、NF Health、配置快照、漂移、告警及 Agent 均只读。GET、刷新、导出、启动不修复来源数据或创建索引。

## 3. 计划模型与范围

计划包含：服务端生成的 planId、名称／说明、revision、enabled／archived、范围选择器、检查集合、配置证据年龄策略、schedule、scheduleRevision、授权主体与创建／更新时间。新建默认暂停，启用为直接受治理操作，不引入审批工单。

- 范围模式互斥：现有分组选择器，或最多 200 个明确资源 UUID；禁止同时传两套并集语义。全网计划必须显式选择，不能由空表单隐含产生。
- 分组条件支持站点、主机、networkKey、运营商显示名、PLMN、domain，并沿用现有交集语义；首版排除退役资源。
- 保存／启用时做服务器端有界预览。每次执行按当时成员重新解析；保存原条件、当次资源／Agent 身份及必要展示元数据、范围摘要与指纹。
- 资源成员与 Agent 分组分别报告完整性。身份解析失败、超预算、部分遍历均不得退化成全网查询；保存明确的范围失败记录。
- 空范围显示“未找到巡检对象”，结论为无法判定，不显示通过。部分缺少监测的网元必须出现在分母内。
- 仅 `network_function`／`network_function_instance` 进入网元检查分母，站点和主机保留为范围上下文。相同进程名、IP、主机名不合并资源。
- 范围中未支持远端监测／配置来源的资源返回未配置或不支持，不能由 Agent 在线替代网元健康。

## 4. 五类检查及判定

首版检查类型为服务端闭集，不允许用户输入脚本、SQL、URL、文件路径或任意表达式。五类默认选中；计划可以关闭某类，关闭项明确列为未检查，不参与通过分母。

| 检查 | 使用的证据与结论 |
|---|---|
| 监测覆盖／网元健康 | 遍历范围内应检查的 NF，确认目标及启用状态；复用既有测量和新鲜度，保留 L1/L2/L3 独立状态。无目标、无有效样本、过期或不支持均不能通过；最新采集失败要展示，不能被较老的成功遮盖。某层不支持不妨碍展示其他层，但不得形成完整服务健康结论。 |
| 配置采集／基线 | 对明确绑定的声明来源检查最新已发布观测、观测失败、generation、pending、基线是否存在且适用。目录未配置与范围内没有来源分别给原因；不能据此声称主机没有配置文件。 |
| 配置漂移 | 读取现有漂移评估与未结束周期。策略关闭、无基线、进度落后、pending、generation 不兼容或新证据不足均显式未知／未纳管。告警仍未结束时保留问题，不能靠本次读不到比较结果消除；巡检不发布基线或改变周期。 |
| 未结束告警 | NF 告警与配置漂移分别统计，保留各自身份、严重度、确认与结束语义；已确认但未结束仍是待关注。成功读取且为零，仅表示当次读取未见匹配告警。 |
| Agent 连接 | 检查明确归属范围的已登记远端 Agent，使用中心接收时间及现有 pending／online／stale／offline／disabled 判定；禁用为未纳管，断联不能判断 NF 停止，也不能推导历史可用率。无匹配登记显示覆盖未知，不从空列表推断无需 Agent。本机计划可关闭此类检查并显示未检查，不要求为本机另外部署远端 Agent；本期不推断还应安装多少 Agent。 |

配置新鲜度：计划必须保存 `configMaxAgeSeconds`，默认建议 86400 秒，可在 300 至 604800 秒内选择。调度采集来源的有效阈值取计划上限与“来源 intervalSeconds + 固定 300 秒宽限”中的较小值；手动来源使用计划上限。阈值与策略版本写入报告。只使用已发布观测的真实时间；未来或无效时间为未知，失败观测不刷新成功证据的年龄。

NF Health 和 Agent 使用各自已有新鲜度权威，不另外发明一套健康阈值。告警读取时间表示读取新鲜度，不把告警首次发生时间当作过期依据。

## 5. 执行状态、发现、完整性与时间

四个维度独立保存并展示：

| 维度 | 拟定取值／含义 |
|---|---|
| 执行状态 | `queued/running/completed/failed/interrupted/missed/skipped`；completed 表示执行流程产出了报告，仍可能有问题或数据缺口。 |
| 检查项结果 | `pass/finding/unknown/not_applicable`；finding 附 warning／critical 与原因，unknown 附未配置／过期／读取失败等原因。 |
| 读取完整性 | 每个来源独立 `complete/partial/unavailable`，保留读取数量、上限和原因；读取完整不等于服务健康。 |
| 总体结论 | 有已证实问题时显示“发现问题”，同时展示缺口；无问题但存在必查 unknown／部分读取时为“无法完整判定”；只有非空必查集合全部通过时才为“检查通过”。 |

- 不设虚构健康分、SLA、可用率或自动根因置信度。通过／问题／未知的计数按整个固化报告计算，不按当前分页计算。
- 记录 scheduledFor、queuedAt、startedAt、finishedAt；每类来源另存 readAt，每条证据另存 collectedAt／lastReceivedAt 和年龄阈值。
- 报告描述执行区间内的已存证据，跨来源为最终一致；不声称所有数据来自同一瞬间或 Mongo 事务快照。最新 Agent 记录无法重建历史状态。
- 固定报告包含当次安全结论和依据，不仅保存外部 ID。来源样本将来过期后报告仍可读；来源链接失效要提示。
- 只保存必要标量、状态、原因、版本与引用，不保存配置正文／投影／指纹、日志正文、原始指标数组、数据库凭据或 Agent 密钥。
- 历史页面刷新、CSV／JSON 导出读取同一 run 的已保存结果，绝不重新查询来源改写报告。活动任务中间状态明确标为暂未完成。

## 6. 调度与故障恢复

首版 UI 提供固定间隔（15 分钟／1 小时／4 小时）、每天、每周；不开放原始 Cron。日历计划保存 IANA 时区，默认 `Asia/Shanghai`，预览后五次执行；持久化时间为 UTC，UI 同时显示计划时区与用户本地时间。

- 日／周周期按当地日历推进，不能简单加 24 小时；夏令时缺失时刻跳过并记录，重复时刻只按首次出现执行一次。固定间隔按 UTC 实际时长推进。
- 首版一个 Go controller 内运行，两个 worker、每计划最多一个活动任务，手动与自动共用限制；后台不经内部 HTTP 请求模拟用户。
- 每次自动触发以 planId、scheduleRevision、scheduledFor 生成唯一 occurrenceKey；手动唯一键为 planId、主体、requestId，另存规范化请求摘要。同键同摘要返回原 run，同键不同摘要返回 409；创建计划同样采用主体与 requestId 的唯一键及摘要校验。返回 202 后任务已持久化，断开浏览器不取消任务。
- Mongo 单文档 CAS／租约令牌控制计划占用，runId 先保存在计划内有限调度日志，再幂等投影执行记录；不用跨集合事务，不声称采集或进程执行 exactly-once。
- 租约过期后的旧 worker 无权覆盖新结果。崩溃记录关闭为 interrupted，保留已保存的有限诊断；用户重跑创建新 run，不能用新证据补成旧时刻的报告。
- 手动重复执行冲突返回现有活动 run 链接；定时遇同计划在执行，写明 skipped／busy。全局繁忙保持有界待执行，不无限增建队列。
- 漏跑宽限 5 分钟；宽限内可延迟执行并显示实际延迟，超过时写 missed 并推进下一时刻。长时间停机只保留一条汇总漏跑记录及区间／数量，不逐次补跑，也不伪造当时证据。
- 计划修改／暂停使用 revision；已取得开始授权的任务按原计划快照完成，尚未开始的任务在执行前重验。改变 schedule 推进 scheduleRevision，失效旧未开始触发；归档要求禁用且没有活动任务。
- 自动任务使用启用／重要变更时确认的 authorizedBy。每次开跑前向现有用户权威重新检查其启用状态与 core.configure；失权时暂停后续调度，显示 authorization_lost。重新启用或改变关键定义由当前合法操作者重新授权，不伪造浏览器会话。

## 7. Ops 数据、API、权限与边界

拟新增 `xcloud_ops.app_inspection_plans` 和 `app_inspection_runs`。计划保存当前定义及有限调度日志；run 保存计划快照、范围快照、检查版本、状态、来源覆盖和安全结果。结果数组控制在 2 MiB 内，因此首版 items 可在 run 中原子发布、服务端游标投影，不另建无界结果集合。

索引以 `backend/cmd/inspections-init` 显式初始化，默认无连接 dry-run，`--apply` 仅创建本模块索引。计划到期查询、occurrenceKey 唯一、手动 requestKey 部分唯一、执行目录和终态过期索引分别设计；没有 requestKey 的自动记录不能被错误的唯一 null 索引互相冲突。

终态报告默认最多保留 90 天，仅终态写 expiresAt；活动 run 和计划不设 TTL。归档计划保留可追溯元数据。提供容量统计和显式准入保护；初始建议终态存储预算 1 GiB，超预算拒绝新执行并展示原因，不提前静默删除历史。容量保护实现必须在上线前以并发／过量 fixture 验证。

| Method | 拟新增路径 | 语义 |
|---|---|---|
| GET | `/api/inspections/meta` | 能力、边界、调度器状态、容量和配置状态。 |
| GET | `/api/inspection-plans` | 计划目录，筛选和游标。 |
| POST | `/api/inspection-plans/preview` | 语义只读：校验定义、范围、年龄策略及后五次执行。 |
| POST | `/api/inspection-plans` | 幂等创建，默认暂停。 |
| GET | `/api/inspection-plans/{planId}` | 计划详情和当前调度状态。 |
| PUT | `/api/inspection-plans/{planId}` | CAS 编辑、启停和归档。 |
| POST | `/api/inspection-plans/{planId}/runs` | 幂等创建手动执行，绑定 expectedRevision。 |
| GET | `/api/inspection-runs` | 执行目录，计划／状态／结论／范围筛选。 |
| GET | `/api/inspection-runs/{runId}` | 固定执行摘要、范围和来源覆盖。 |
| GET | `/api/inspection-runs/{runId}/items` | 固定结果的筛选／游标分页。 |
| GET | `/api/inspection-runs/{runId}/export` | 同一固定结果的 CSV／JSON。 |

这是 11 个拟定新增 METHOD+PATH，不提前修改现有生产路由数；实施时从真实注册集合派生并更新所有契约。现有 API、构造器和查询语义保持兼容，必要能力采用新增方法或适配器。

读取／导出需要现有 cookie 会话与 core.read；预览需要 core.configure；创建、编辑、启停、归档和手动执行需要 core.configure、Fresh Actor、域校验、幂等／CAS 及 best-effort 审计。viewer 不能执行任务。后台执行另按上一节重验授权主体。

响应 no-store，查询／请求体使用闭集且有界；审计只保存身份、计划／执行 ID、revision、状态与范围摘要，不复制自由文本或报告正文。CSV 沿用公式注入防护，导出最多 10000 行／10 MiB；JSON 同样按安全投影和体积限制。无 source 数据跨库写，无新认证模型、审批或租户模型。

## 8. 初始执行预算

以下为首版设计上限，实施基准必须验证，不能用扩大超时掩盖问题：

| 项目 | 初始预算 |
|---|---|
| 非归档计划／全局活动 run／单计划活动 run | 100／2／1。 |
| 调度扫描／等待队列 | 15 秒 tick，有界分批；最多 20 个 queued，满时显式 backpressure。 |
| 每次范围 | 最多 200 个资源、100 个 Agent、128 个声明来源；既有遍历深度／边数上限仍有效。 |
| 单次执行／单次 Mongo 查询 | 30 秒／2 秒，传递 context 取消；独立来源失败保留其他证据。 |
| 结果／分页 | 最多 2000 项、每 run 2 MiB；每页 50，最大 200，稳定 key 与作用域绑定游标。 |
| API 限流 | 读取 120／分钟，预览与写 30／分钟，手动触发 10／分钟，导出 10／分钟，按主体与端点。 |

范围越界在执行前失败，不截断成“全量检查通过”。读取中出现 limit+1、时限或内容预算边界则记录 partial／unavailable，保留已经读取部分及明确原因；不能补零。

## 9. 页面、对比与既有闭环

页面结构按 [DESIGN_BRIEF.md](DESIGN_BRIEF.md)。入口加入现有运维导航与路由契约；分组页带入当前范围。列表筛选／游标／视图写入 URL，详情保留安全返回上下文。

- 执行页明确区分 planned time、实际开始、完成时间和证据时间；无来源目录、空范围、未配置、过期、部分读取、执行失败分别有可操作文案。
- 上次对比只针对同计划、兼容检查版本／策略和相同条目身份；范围新增／移出单列，条目无法比较则说明原因。
- 上次 finding 本次获得有效 pass 可显示“本次未再检出”；unknown、条目消失、配置换代或基线替换不能显示恢复。巡检变化不修改原告警生命周期。
- 原告警引用可进入已有调查创建入口；无告警锚点的巡检发现仅进入对应资源／配置／Agent 页面，不虚构告警或扩展调查 anchorKind。
- 固定报告的导出只读 run；跳转现有 `/ops-reports` 时明确是“查看当前运维报表”，不冒充该 run 的同一数据库快照。
- 首版不新增巡检异常通知、告警主体或 escalation。已有 NF／漂移告警照常通知，避免相同问题因巡检频率重复推送。

## 10. 分批交付与验收

按 [TASKS.md](TASKS.md) 的垂直切片执行。每个切片同时包含后端、可用页面、错误状态和必要验证；先证明一个手动运行的完整闭环，再开放自动调度。

必须通过：

1. 单计划手动执行并刷新／重开页面后，范围、结果、计数和 CSV／JSON 保持同一 run 内容；源数据变化只影响新 run。
2. 旧成功后出现失败、过期、未来时间、无目标、无基线、漂移 pending、源不可用、空范围和越界，都不能变成通过或零问题。
3. 同时触发、响应丢失重试、调度重复 tick、租约过期、进程中断、长停机、时间回拨、DST、计划编辑／停用和用户失权有确定可验证结果。
4. 范围退役／换组／新增／移出保持历史不变；范围失败不扩大，Agent 不通过名称与 NF 合并，比较不制造恢复。
5. viewer 写 403，陈旧 session／角色变化被拒绝，CAS 冲突保留前端草稿；越界导出、公式前缀和敏感字段检查通过。
6. 独占临时 Mongo 的实际唯一索引／CAS／崩溃恢复／保留测试通过；fake clock 验证时间行为，不用长时间 sleep 代替测试。
