# 站点／网络工作台使用与核查

入口：资产工作台 → 站点／网络，规范地址 `/inventory/groups`。
本文描述源码中的功能；实际服务是否已更新，需要部署后另行核查。

## 建立站点和主机关系

1. admin 或 operator 点击“创建站点”，填写机器名称、显示名称、描述和生命周期。跨域站点默认使用 platform 域，初始生命周期建议 planned。
2. 需要网络分组时，显式增加网络键、运营商名称和 PLMN。机器网络键稳定且区分大小写规则限定为小写；运营商名称只是管理标签。
3. 在既有资产台账中创建或选择主机资源。主机 UUID 是身份，IP 和主机名不能替代它。
4. 打开“站点／主机关系”，搜索并选择规范站点和主机，提交新增 contains 关系。每次提交单独生效。
5. 在“资源”和“归属检查”中核对关系。站点声明某个网络，不会自动给所有子资源声明同一网络；需要按资源维护“网络归属”。

显示 planned/active 只描述资产生命周期，不代表进程运行或服务健康。
同一资源可以显式属于多个网络，同一 UUID 不会因此复制成多个资产。

## 维护 Agent 归属

Agent 访问与管理归属仍由 admin 在 Agent 管理页维护：网络键、运营商名称、
站点 UUID、主机 UUID、PLMN。operator 和 viewer 在本工作台只读 Agent。

Agent 声明站点和主机，不会自动生成 Topology 边；站点／主机资源分别存在也不
证明二者具有包含关系。声明不一致时，先核对两个来源，再在各自权威页面修正。
远端进程观测不会自动成为纳管 NF，也不会改变已有本机日志或监测范围。

## 按范围核查

- 左侧按站点或网络浏览，网络下可以继续选择相关站点。当前网络、站点、主机、PLMN 等条件持续显示在范围条中，可逐项清除。
- 选定站点后可展开其包含的主机。该目录用于组织导航；右侧资源仍按网络等显式条件求交，主机被列在目录中不表示它继承了站点网络声明。
- 主机、逻辑 NF、NF 实例和 Agent 使用各自的分母。共享组之间的数字不能直接相加。
- “资源”中的目标关联只适用于 NF；主机测量从明确绑定的 Agent 查看。多个采集节点不会被静默合并成一套主机测量。
- “未关闭告警”包含 active、acknowledged、assigned、recovering，计数覆盖整个范围。点击告警在新标签页打开原告警证据。
- “配置证据”只包括显式绑定当前资源 UUID 的来源。配置路径继续由部署清单按实际 EPC/5GC、IMS 环境声明，不会因选择站点自动扫描目录。
- 配置来源总数、可比较证据、无基线、最近尝试失败分别核查；没有变化记录不能证明当前所有文件一致。
- “归属检查”中的共享路径本身不是故障。读取失败和遍历上限是待解析，不能当成未归属。

“读取完整”只表示相关查询完成，不代表所有资源健康或已经采集过测量。
源失败或超限时总数显示不可用；已观察条数不能当作全站总量。
UI 中显示的服务器接收时间、测量时间、配置观测时间各有含义，不能互相替代。

## 调整关系和退役

迁站通过新增新关系、核查结果、退役旧关系分别进行。旧边退役需要原因和原版本。
中途失败时，按实际读取结果处理：可能暂时同时属于两个站点，也可能仍保留旧边；
不要重复提交或把部分成功解释为迁站完成。冲突后重新读取，不覆盖别人已保存的版本。

站点退役保留原记录及关联，不级联删除或退役主机、网元、Agent、告警和配置证据。
新增关系不接受已经退役的对象。需要查看退役记录时选择“包含退役资源”；仍然只
使用当前活动包含关系，不恢复已退役的历史边。

## 报表与导出

“打开范围报表”携带网络／站点／主机／运营商名称／PLMN／域条件。
报表使用“按当前归属筛选历史证据”的口径，不重建事件发生时的站点归属。
Agent 分区只有当前状态，不能据此计算站点历史可用率。

首次生成相对窗口后，分页和 CSV 使用服务端确定的同一绝对时间窗。归属或时间窗
变化导致游标失效时，从首个分页重新生成，不去掉筛选条件获取全局数据。
导出保留七天窗口、10000 行和 10MiB 限制，并在原列之后附带分组元数据。

Inventory 详情返回时恢复工作台的范围。跨实体详情在新标签页打开，原工作台保留。

## 运维与验收边界

工作台没有独立环境变量、远程命令或独立数据库。NF Health、Agent、配置来源继续
遵守原部署与权限规则。运营商标签不是租户隔离，PLMN 字符串不是漫游协议。

只读分组查询不会创建索引。部署规模扩大时，应先检查网络属性、Agent 站点／主机
查询的实际执行计划；当前缺少相应专用索引，详见架构文档的 PERFORMANCE_FINDING。
索引调整由运维人员使用统一索引权威实施，不能在读取接口中隐式完成。

真实多主机验收需要第二个 Linux Agent、HTTPS 入口和明确的资源／归属清单。
隔离演示中的 DEMO 数据和 fixture principal 只证明流程与投影，不替代真实节点、
生产登录或 TLS 的验收结果。

架构与边界见 [站点／网络工作台](../architecture/site-network-workbench.md)。
