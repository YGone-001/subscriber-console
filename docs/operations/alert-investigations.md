# 告警排障工作台操作说明

入口：网元告警的“进入排障”，或网络态势中的“告警排障”。

## 使用流程

1. 在告警队列打开一条告警，进入排障。起始资源来自告警的 resourceId，不以网元名称匹配。
2. 核对时间窗与各来源读取状态。默认首次触发前后各 30 分钟，终点不超过读取时刻；可选择最长 24 小时。
3. 按告警事件、健康采集或配置观测筛选时间线。展开事件可查看标识和关联依据，跳转原工作台进一步检查。
4. 当前声明关系仅是一跳邻接，不证明故障发生时的关系或影响传播。日志入口复用已明确声明的资源来源。
5. 建立排障记录，填写备注、人工结论并显式关联知识条目。管理员／操作员可写，查看员只读。
6. 结案需要填写结论并确认。结案仅改变排障记录，不清除告警、不修改网元。需要继续调查时可以手动改回排查中。

## 解释证据

- “有界读取成功”表示查询成功，不表示历史覆盖完整或业务健康。
- 空结果不能证明没有故障、没有配置变化，或设备离线／在线。
- 采集尝试成功不能替代 L1/L2/L3 测量结论；测量时间单独呈现，样本身份或时间不匹配时不附加健康结论。
- 配置变化只表示两次观测之间内容不同；采集时间不是精确修改时间，变化不自动等同偏离基线或根因。
- 部分、失败、达到上限和关联缺失会分别显示。来源错误不会伪装成零记录。
- 已保存记录的资源和时间窗不可被浏览器覆盖；证据每次重新读取，不是假定永久保留的故障快照。
- 所属工作台链接打开其当前视图；时间线保留记录自身的观测标识和时间。

## 编辑与并发

每次保存均重新鉴权并携带版本。发生冲突时保留草稿，不自动重试或覆盖其他人的修改。“重新加载当前记录”会在有草稿时要求确认放弃。刷新证据不会覆盖编辑草稿。最近变更只展示最多 20 条 actor／状态元数据，不是完整修改内容历史。

请勿在备注中粘贴口令、鉴权材料或含敏感信息的原始报文。知识条目由知识库维护，本模块只保存显式关联标识；已删除条目显示为不可用。

## 部署与索引

更新包含前端 SPA 的 Go 构建后，由环境拥有者按 [生产拓扑](../architecture/production-topology.md) 更新实际服务。本功能不会自动重启或替换现有服务。

新增记录集合使用当前 Ops 数据库。查看新集合索引计划：

~~~bash
cd backend
GOTOOLCHAIN=go1.24.4 go run ./cmd/investigations-init
~~~

此命令默认 DRY_RUN，不连接数据库。拥有者审核后，使用与服务一致的 MONGODB_URI 和可选 MONGODB_APP_DB 执行：

~~~bash
GOTOOLCHAIN=go1.24.4 go run ./cmd/investigations-init --apply
~~~

--apply 只创建 app_investigations 的目录索引，不迁移或修复数据。开发验收不执行生产索引操作。跨来源查询有独立超时，真实规模下应检查资源索引和执行计划；不能通过扩大超时或补零掩盖读取失败。

## 隔离验证

~~~bash
cd backend
INVESTIGATION_TEST_MONGOD=1 GOTOOLCHAIN=go1.24.4 go test -race -count=1 ./internal/investigation
~~~

该测试拥有自己的临时 Mongo 进程和数据目录，不在生产库插入测试身份、告警或配置。浏览器夹具使用合成身份，不证明生产认证或真实故障处置效果。部署后的真实来源覆盖、现场操作与历史保留验证须单独记录。
