# 定时巡检操作说明

巡检汇总现有证据并检查新鲜度，不触发新采集。源数据需要由现有 NF
Health、配置采集、漂移引擎或 Agent 先行产生；没有来源时界面显示缺口。

## 初始化

从 backend 模块运行，先查看 dry-run：

```sh
go run ./cmd/inspections-init
```

确认 `MONGODB_URI` 和 `MONGODB_APP_DB` 指向预期部署环境后，使用同一受控
环境执行：

```sh
go run ./cmd/inspections-init --apply
```

此命令只建立巡检计划／执行索引，不创建计划、不启用调度、不采集、不建立
配置基线。无需在聊天或命令行参数中提供数据库密码。其他域的索引仍按各自
操作说明管理。

## 切换已有受管理开发进程

此段适用于当前项目的 `local:dev` 开发环境。若旧 Go/Vite 由 root 启动，
agent-dev 不能通过所有权校验停止它们。由原启动用户在 Linux 终端执行：

```sh
cd /home/agent-dev/project/linux-subscriber-console
npm run local:stop
```

停止命令只处理已登记且身份匹配的本项目 Go/Vite；MongoDB 保持现有运行方式。
若报告身份不匹配，应先核对进程，不要直接按端口杀进程。

随后在 agent-dev 终端启动，避免重新产生 root 所有的构建文件：

```sh
cd /home/agent-dev/project/linux-subscriber-console
export PATH=/usr/local/go/bin:$PATH
export GOCACHE=/tmp/xcloud-go-cache-agent-dev
npm run local:dev
```

项目启动器读取原 `.env`。若索引尚未初始化，可用 Node 22 的环境文件加载
方式传递同一配置，无需将数据库密码拼接到命令行：

```sh
node --env-file=.env --input-type=module -e 'import {spawnSync} from "node:child_process"; process.exit(spawnSync("/usr/local/go/bin/go", ["run", "./cmd/inspections-init", "--apply"], {cwd:"backend", env:process.env, stdio:"inherit"}).status ?? 1)'
```

启动后执行 `npm run local:doctor`，再登录 `/inspections`。先创建暂停计划，
手动检查真实来源、范围和报告，再启用定时计划。其他部署方式沿用已有部署
runbook，不使用这段开发进程切换命令。

## 创建与手动验证

1. 打开“定时巡检”，选择“创建巡检计划”；也可在站点／网络分组页带入范围。
2. 输入名称，选择分组条件或通过 Inventory 搜索指定资源。“全部当前资源”
   是显式选项，最多 200 个资源；多个分组条件取交集。
3. 选择检查项目和配置证据年龄。只检查本机时可以关闭远端 Agent 类别。
4. 设置间隔或日／周计划及时区，点击“预览范围与时间”，确认当次成员和后
   五次有效执行时间。
5. 保存为暂停计划，在详情点击“立即巡检”，查看执行记录和报告。
6. 确认来源和范围符合预期后，再启用定时计划。操作者须有 core.configure。

刷新只读取当前记录。“立即巡检”创建新记录；浏览器关闭后已入队任务仍然
存在。重复提交同一请求返回原执行；已有活动任务时应查看该活动记录。

## 阅读报告

“执行完成”表示流程生成了报告；“检查通过／发现问题／无法完整判定”是另
一个维度。没有对象、没有监测、无有效样本、证据过期、来源不可用和不支持
的层次都不会被当作通过。已确认但未结束的告警仍列为问题。

每份报告保存计划版本、执行时间、当次范围、检查项、来源读取时间、证据
时间及判定依据。通过数量是检查项数量，不是服务可用率。Agent 在线也不能
替代网元健康。

展开检查项可进入来源页面。有原告警身份的发现可以进入现有故障调查，继续
保存人工结论和知识引用；巡检自身不改变原告警状态，也不自动修复问题。

上次对比中的“本次未再检出”需要有效的新证据。未知、范围移出、配置换代
和不兼容基线不会标记恢复。历史报告保持原结果，来源页面则可能展示较新的
内容或因样本过期而不可用。

新报告的范围增删明细分别列出资源和 Agent 的身份及当次保存的名称；移出
成员使用上次报告的名称，不依赖当前目录。两次范围读取均完整才生成该类
明细，读取不完整显示不可用；旧报告未保存明细时也显示不可用，不补写历史。
成员改名或 Agent 归属版本变化不算增删。上方增删计数统计的是检查项，与
成员数量可能不同；JSON 和 CSV 的 comparison 字段保存同一份成员明细。

CSV／JSON 来自同一份已保存报告。执行进行中不能导出终态报告；导出保留当
次范围、时间、缺口及原因，不会重新查询网元或配置。

## 调度异常与维护

- 漏跑超过五分钟后仅保存漏跑区间／数量，不使用后来证据补成过去的巡检。
- 服务中断导致租约过期后，原执行标为中断；旧 worker 无权覆盖恢复结果。
- 同一计划仍在执行时，定时触发记录为跳过。全局队列或容量达到上限会显示
  原因，既有报告保留。
- 修改或暂停计划后，尚未开始的旧版本任务不会继续按旧范围执行；已经开
  始的执行按原快照完成。暂停不会关闭现有 NF／配置漂移告警。
- 自动任务的授权人失权、锁定或禁用时，计划暂停。合法操作者检查范围后
  重新启用；无需审批工单。
- 夏令时重复分钟只执行第一次；不存在的当地时刻记录跳过。固定间隔按实
  际经过时间运行，不按当地 24 小时推算。
- 归档需要先暂停并等待活动任务结束。归档不可继续执行或编辑，既有报告
  仍按保留策略保存。

报告默认最多保留 90 天；512 个最大体积预留槽位构成 1 GiB 报告预算，容量
满后停止接收新执行，不提前静默删除旧报告。TTL 删除可能晚于到期时间，待
数据库完成过期处理后容量才释放。计划和运行中记录不设置 TTL。

## 验收与证据边界

隔离 MongoDB、合成资源、fake clock、浏览器测试、构建和现场验收分别记录。
现场启用前应确认真实资源归属、源采集周期、配置目录／基线、漂移进度及
Agent 覆盖。真实多主机观测范围仍受现有 Agent 能力约束。

权限、服务启停和固定端口遵循现有部署流程。停用巡检调度会停止新任务，
保留报告；本模块没有网络配置回滚操作。
