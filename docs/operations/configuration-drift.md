# 配置漂移告警操作说明

配置漂移监测已有本机声明来源和人工基线。入口是配置快照的来源详情，以及网元告警中的“配置漂移”视图。监测默认关闭；操作员或管理员可以设置策略，查看员只读。

## 准备来源

部署声明仍由 CONFIG_SNAPSHOT_MANIFEST 指定，指纹私钥仍由 CONFIG_SNAPSHOT_KEY_FILE 指定。浏览器只提交来源 ID，不提交配置文件路径。调整声明与密钥后由环境拥有者按现有部署流程生效。

当前默认样例是 [config-snapshots.json](../../deploy/examples/config-snapshots.json)，配置根为 /etc/xCloud，共 54 条明确路径。EPC/5GC 使用 gnc/gdm/gdg/gpc/gsp，CSCF/SMSC 使用 gcc，IPSMGW 使用 gnc/ipsmgw。MME 示例为 /etc/xCloud/gnc/mme/mme.yaml 和 /etc/xCloud/gnc/mme/diameter/mme.conf。私钥、证书、数据库、动态库加载辅助声明和安装脚本不纳入此样例。

样例不自动加载，也不证明网元已安装。每次实际部署需要选择允许采集的文件、指定稳定 collectorId/sourceId、明确绑定 Inventory resourceId，并按实际路径调整。旧的源码安装目录声明保留在 [config-snapshots-source-tree.json](../../deploy/examples/config-snapshots-source-tree.json)，仅适用于明确选择的旧布局，不是当前默认或自动回退。

定时采集仍由声明的 intervalSeconds 决定；0 表示手动。启用告警不会自动改采集间隔或采集文件。deb 安装台、包安装后自动登记和首次基线初始化属于后续功能。

## 初始化索引

从 backend 目录运行，默认只打印计划，不连接数据库：

~~~bash
go run ./cmd/config-drift-init
~~~

由环境拥有者使用现有受控 MongoDB 环境配置，在核对干运行结果后创建漂移索引：

~~~bash
go run ./cmd/config-drift-init --apply
~~~

命令读取 MONGODB_URI 和可选 MONGODB_APP_DB；默认 Ops 数据库名为 xcloud_ops。它只创建此模块的索引，不改订阅者、业务配置或网元文件，不重启服务。

## 开始监测

1. 打开“配置快照”，进入已明确关联资源的来源，执行采集。
2. 查看安全投影或元数据模式，选择已接受的兼容版本作为基线。
3. 在“配置漂移监测”中勾选启用，选择严重度并保存。开启后从下一次已发布观测开始评估。
4. 手动再次采集，或等待已声明的定时采集。界面分别展示采集状态、最近有效比较、评估状态、新鲜度与已处理／已发布序号。
5. 若观测与基线不同，点击当前漂移事件，或到“网元告警 → 配置漂移”按来源、资源、站点和网络筛选。

来源未关联有效资源时不能启用；没有基线时不会新开漂移告警。手动来源的“最近有效观测”只代表该时点，不能证明当前文件仍未变化。

## 处置与结束

确认告警只记录已知悉，不关闭漂移，不接受新基线，不写网元配置。相同周期持续观测到差异时只更新同一事件。缺文件、读取失败、发布中断或不兼容不会被当成恢复。

人工恢复文件后，在新采集中确认其回到原基线，才产生“已验证恢复到基线”。更换或清除基线、关闭策略、撤回来源或退役资源会记录相应行政结束原因。替换基线表示接受新的比较参照，不代表修复；新周期仍需要新观测。

详情中的“比较基线与触发版本／最近证据”始终绑定该事件的固定基线。元数据模式只能证明内容有差异，不能推断具体秘密字段。旧版本因独立保留策略不可用时，安全差异入口明确报不可用。

可从事件进入人工排障，保存备注、结论和显式知识引用。结案只修改排障记录，不关闭漂移告警，不执行网络操作。

## 通知

打开通知设置，先配置既有 webhook 渠道，再在升级规则中明确选择“配置漂移告警”或两个类别。既有升级规则没有新类别字段时仍只处理网元健康告警。配置来源筛选可留空或填写最多 128 个明确 UUID；规则 ID 筛选继续仅属于 NF 告警。

开启和真实恢复生成投递意图；行政结束不冒充恢复通知。详情展示本事件的投递状态和分页。pending 表示尚未发送，sent 表示接收端返回成功响应，不等于业务处置已完成。只有后台通知 worker 访问接收端，网络递送为至少一次，接收端应使用幂等键去重。

## 故障与保留

队列、处理序号和 worker 状态用于识别积压。每来源队列最多 256 输入，满时对新发布／控制变更施加背压，不丢输入。重启后按持久化发布日志和投影日志恢复，GET 不进行修复或采集。CAS 冲突需要核对当前版本；策略草稿保留，由操作员明确选择是否使用当前版本重试。

后台每小时有界清理超过 90 天的已结束事件。开启事件、待发布投影和未完成投递受到保护；保护扫描超界时停止清理并报告处理失败。配置快照保留期仍独立适用。不要手动删除 source journal、Pending、基线或唯一索引来处理积压。

源码构建、隔离 MongoDB、合成浏览器场景与真实部署验收分别记录。部署后由环境拥有者使用明确的测试来源验证一次变更、重复采集、失败不恢复、文件回基线、通知接收和排障记录；不使用生产网元配置做未经规划的试验。
