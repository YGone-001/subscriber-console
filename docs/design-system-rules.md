# UI 设计系统规则

本规范适用于 `subscriber-console` 的新增页面、组件重构与设计评审，覆盖 token、表格、表单、图表和响应式设计。它以当前浅色/深色主题、运营后台的数据密度、中文/英文双语和键盘操作为基础。

文中的“必须”是合并前要求，“应该”允许在评审中说明理由后例外。存量代码采用触达即迁移，不要求一次性重写。

## 1. Token 规则

### 1.1 三层架构

所有视觉值按以下三层组织。组件不得直接使用未声明的视觉字面量：

1. **原始 token（reference）**：无业务含义的固定值，例如 `--ref-color-teal-600`、`--ref-space-4`。
2. **语义 token（system）**：描述用途并随主题变化，例如 `--sys-color-text-primary`、`--sys-color-action-primary`。
3. **组件 token（component）**：只在组件确有独立契约时定义，例如 `--cmp-table-row-height`、`--cmp-input-height`。主题相关颜色必须引用语义 token；主题无关的间距、圆角和时长可以引用原始 token。

命名统一使用 `--{层级}-{类别}-{属性}-{变体}-{状态}`，从左到右由稳定到具体：

```css
:root {
  --ref-color-teal-600: #087f8c;
  --ref-color-canvas-light: #f3f6f7;
  --ref-color-panel-light: #ffffff;
  --ref-space-4: 16px;
  --ref-radius-md: 8px;
}

[data-theme="light"] {
  --sys-color-action-primary: var(--ref-color-teal-600);
  --sys-color-surface-canvas: var(--ref-color-canvas-light);
  --sys-color-surface-panel: var(--ref-color-panel-light);
}

.data-table {
  --cmp-table-row-height: 54px;
  color: var(--sys-color-text-primary);
}
```

原始 token 和跨页面语义 token 放在 `src/app/globals.css`；页面或组件特有 token 放在对应的同目录样式文件。全局样式只承载真正全局的基础样式和 token，避免页面样式在路由切换后发生级联冲突。

### 1.2 基础尺度

| 类别 | 允许值 / 规则 |
| --- | --- |
| 间距 | `0, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64px`；默认 4px 基准 |
| 字号 / 行高 | `12/16, 14/20, 16/24, 18/26, 24/32, 32/40px` |
| 字重 | 正文使用 `400/500`，界面强调使用 `600/650`，标签和紧凑状态使用 `700/750`；`800` 只保留给短小运营标记和存量兼容，不使用 `900` |
| 圆角 | 微型元素 `4/6px`、小型导航和标签 `7px`、控件 `8px`、主要面板 `10px`、柔和内容卡 `12px`、胶囊 `999px` |
| 控件高度 | 紧凑 `32px`、默认 `36px`、触控/大型 `44px` |
| 动效时长 | 快 `150ms`、常规 `200ms`、慢 `350ms` |
| 层级 | 基础 `0`、吸顶 `10`、下拉 `20`、遮罩 `30`、弹窗 `40`、通知 `50` |

文本、表格数字、图表刻度采用相同的排版 token。IMSI、金额、流量、日期和计数必须使用 `font-variant-numeric: tabular-nums`；标识符可使用等宽字体，但正文不得使用等宽字体。

### 1.3 颜色与主题

- 语义颜色至少覆盖：画布、面板、悬浮面、主/次文字、弱化文字、边框、主操作、成功、警告、危险、信息、焦点环和遮罩。
- 浅色与深色主题必须定义相同的一组语义 token；禁止只为某一主题增加组件内硬编码覆盖。
- 正文和背景对比度至少为 `4.5:1`，大字和非文本控件边界至少为 `3:1`。状态不能只用颜色表达，必须同时有文字、图标、形状或纹理。
- 新增 CSS/TSX 禁止直接写 `#hex`、`rgb()` 或 `rgba()`；原始 token 声明、第三方库必要覆盖和统一图表色板可以进入集中维护的允许清单。
- 当前 `--background`、`--surface`、`--primary`、`--text-main` 等变量视为兼容别名；重构时逐步映射到 `--sys-*`，不要在同一组件再创造同义名称。

### 1.4 状态、动效与治理

- 每个交互组件至少覆盖 `default / hover / focus-visible / active / disabled / loading / error` 中适用的状态。
- 焦点统一使用语义焦点环；禁止用 `outline: none` 后不提供等价焦点样式。
- 位移和透明度动效使用现有 `fast / normal / slow` 节奏；加载或装饰动效必须服从 `prefers-reduced-motion`。
- 新 token 必须附带用途、主题值和使用示例；同义 token 不得重复创建。删除或改名先保留一个发布周期的兼容别名，并在变更日志记录。

## 2. 表格规则

### 2.1 使用边界与结构

- 表格用于比较多条同构记录；单条详情使用描述列表，少量卡片指标使用卡片，不用表格模拟布局。
- 使用原生 `<table>`、`<thead>`、`<tbody>`、`<th scope="col">` 和 `<td>`。每张表必须有可见标题或仅供读屏器读取的 `<caption>`。
- 标准组成顺序为：标题/说明 → 搜索与筛选 → 批量操作 → 表头 → 数据行 → 加载/空/错误状态 → 分页。
- 列按“选择、主标识、核心状态、主要指标、辅助信息、操作”排序。主标识列和操作列应稳定，低优先级列可以在窄屏隐藏。

### 2.2 尺寸、对齐与内容

| 项目 | 默认规则 |
| --- | --- |
| 行高 | 默认 `54px`；紧凑表可用 `44px`，同一张表不得混用 |
| 单元格内边距 | 水平 `16px`；默认垂直 `12px` |
| 表头 | `12px/16px`、600、弱化文字色；不要用全大写转换中文或长英文 |
| 文本 | 左对齐 |
| 数值、配额、金额 | 右对齐、等宽数字、单位一致 |
| 状态 | 左对齐，使用带文字的状态标记 |
| 行内操作 | 右对齐；常用操作直接显示，其余进入“更多”菜单 |

- 不允许用字号缩小来塞入更多列。长值单行省略时必须能通过聚焦、详情抽屉或显式复制操作获得完整值；关键标识不得仅依赖 hover 的 `title`。
- 空值统一显示 `—`，不要混用空字符串、`N/A`、`null`。日期、流量和数量在同一列使用同一格式和单位。
- 行 hover 只增强定位，不代表选择。选中行必须同时有复选框状态和非颜色提示。

### 2.3 排序、选择与分页

- 可排序表头必须包含真实 `<button type="button">`，点击区域覆盖整个表头内容；不得只给 `<th>` 绑定点击。
- 当前排序列在 `<th>` 上设置 `aria-sort="ascending|descending"`；视觉图标与读屏文本同步。默认未排序图标可弱化，但不可造成所有列都已排序的错觉。
- 全选复选框只选择当前页时，标签必须明确为“选择当前页”；部分选择设置 `indeterminate`。所有复选框都要有可访问名称。
- 默认分页选项统一为 `10 / 20 / 50`；筛选、排序或页大小变化后回到第一页。分页必须显示当前范围和总数，上一页/下一页在边界禁用。
- 数据量较大时使用服务端分页和排序；禁止先下载全量记录再在浏览器切页。

### 2.4 状态与无障碍

- 加载时保留表头和大致列宽，使用 3–5 行骨架；空状态解释原因并给出可执行下一步；错误状态保留筛选条件并提供重试。
- 批量操作后必须反馈成功数、失败数与失败原因，不以关闭弹窗代替反馈。
- 键盘焦点只停在按钮、链接、复选框等交互元素，不让整行无意义进入 Tab 顺序。整行可打开详情时仍需提供明确的链接或按钮。
- 横向滚动容器必须可键盘滚动且有可见滚动提示；吸顶表头不得遮住焦点环。

### 2.5 响应式表格

- `>= 980px` 显示完整运营表格；`761–979px` 优先隐藏辅助列；`<= 760px` 保留主标识、状态和一个核心指标，其余通过带字段标签的记录卡或详情入口获取。
- 列之间存在强比较关系时保留表格并局部横向滚动，不要强行转成卡片；任务以逐条处理为主时才使用列表或记录卡替代视图。
- 窄屏仍需保留批量选择能力。固定列不能遮挡主要内容或操作，评审时检查其占用宽度。操作菜单和分页控件触控目标至少 `44px`。

## 3. 表单规则

### 3.1 布局与字段选择

- 默认使用单列和顶部标签。只有紧密相关且可独立理解的短字段（如数值 + 单位、起止日期）可同排；小于 `768px` 必须回流为单列。
- 长表单按任务分组并使用清晰的分节标题；字段顺序遵循用户心智流程，而不是数据库字段顺序。
- 字段宽度表达预期输入长度：IMSI/MSISDN/密钥可限制合理最大宽度，说明文本和 textarea 使用可读宽度。不得把所有字段机械铺满整行。
- 输入类型必须匹配数据。根据选项数量、标签长度、使用频率和是否需要搜索选择控件：少量稳定的互斥项优先使用 radio，多选使用 checkbox，长列表或可搜索选项使用 select/combobox；日期使用日期控件；长文本使用可调整大小的 textarea；密码或密钥提供显隐切换。

### 3.2 标签、帮助和必填

- 每个控件必须有持久可见的 `<label htmlFor>`，控件具有唯一 `id`；placeholder 只给示例，不承担标签职责。
- 默认标记“可选”字段，不在每个必填项上堆叠星号；若业务场景必须保留星号，表单开头解释其含义，并同时使用原生 `required`。
- 格式说明放在标签下、输入框上方；输入后的动态结果或错误放在控件下方。字符限制从初始状态就显示剩余数量。
- 单位是数据的一部分。复合输入的数值框和单位选择器各自需要标签或可访问名称，并在视觉上作为一组。

### 3.3 校验与提交

- 客户端做即时可修复的格式校验，默认在 `blur` 后触发；用户修正后可以及时清除错误。除搜索建议等场景外，不在每次击键时展示错误。
- 服务端始终再次校验类型、范围、权限和业务冲突；客户端校验不能成为安全边界。错误尽量映射回字段，多字段错误同时提供可聚焦的顶部摘要，并链接到相应字段。
- 错误文案必须说明“哪里错了 + 如何修复”，例如“IMSI 必须是 15 位数字”；禁止只写“无效输入”。错误使用 `aria-invalid="true"`，并通过 `aria-describedby` 关联帮助和错误文本。
- 提交期间禁用重复提交并显示进行中状态，但不清空输入。成功后给出明确结果；失败后保留输入。长表单离开或关闭前确认未保存更改。
- 按影响范围、可逆性和权限判断操作风险。批量修改、余额或策略调整、不可逆删除等高影响操作提交前提供复核摘要，说明影响对象数量与不可逆后果。

### 3.4 敏感数据与无障碍

- K、OP/OPc、密码等敏感值默认遮挡，不写入日志、URL、分析事件或错误文本；复制动作必须明确反馈，离开页面后不继续暴露。
- Tab 顺序与视觉顺序一致。分组使用 `fieldset + legend`；错误摘要获得焦点但不形成焦点陷阱。
- 桌面控件高度至少 `36px`；触控或 `pointer: coarse` 下至少 `44px`。按钮文案使用明确动作，如“保存用户”，不只写“确定”。
- 禁用态只用于真正不可操作的情况；只读数据使用 `readOnly` 和只读说明，避免用 disabled 导致内容不可复制或不被提交。

## 4. 图表规则

### 4.1 图表选择

| 目标 | 首选图表 | 使用限制 |
| --- | --- | --- |
| 分类比较 / Top N | 横向条形图 | 条形从零开始，按值排序 |
| 连续时间趋势 | 折线图 | 同图通常不超过 4 条线 |
| 总量随时间变化 | 面积图 | 面积编码必须有真实零基线 |
| 目标与实际 | 子弹图或带目标线条形图 | 清楚标注目标值 |
| 少量占比 | 环形图 | 仅 2–5 类且总和有意义 |
| 多类占比 | 100% 堆叠条形图或排序条形图 | 超过 5 类不使用饼/环图 |
| 分布 | 直方图或箱线图 | 分箱规则必须稳定并说明 |
| 相关性 | 散点图 | 不暗示因果关系 |

必须选择能回答业务问题的最简单图表。KPI 数字优先直接显示；没有趋势数据时不要添加装饰性 sparkline。

### 4.2 编码、色彩与标注

- 同一指标跨页面使用同一语义色；同一系列的所有条形使用同一色，不用彩虹色制造虚假的类别含义。只有互不相关的类别才使用分类色板。
- 分类色板须同时适配浅色/深色主题并可被常见色觉缺陷区分；成功/失败不得只靠红绿，辅以图标、线型或文字。
- 条形图数值轴从零开始。折线图若截断坐标轴必须显式标注。轴标题包含单位，刻度采用一致格式，网格线弱于数据线。
- 尽可能直接标注系列或关键值；图例靠近图表且顺序与视觉顺序一致。只标注真正的阈值、异常点、目标和关键变化，不为装饰添加注释。
- Tooltip 显示完整系列名、格式化值、单位和时间范围；Tooltip 只能补充详情，核心结论不能只在 hover 后出现。

### 4.3 状态、交互与无障碍

- 每张图都有标题、简短结论或用途说明、数据更新时间，以及可访问的文本摘要。复杂图表提供等价数据表或“查看数据”入口。
- 交互数据点可用键盘访问并有清晰焦点；触控下 Tooltip 可点击打开、点击外部关闭，目标至少 `44px`。
- 加载、空数据、部分数据、错误和过期数据必须分别表达。空数据不绘制零值假图；错误状态提供重试。
- 实时数据更新不应反复打断读屏器。只对用户触发的关键结果使用礼貌级 `aria-live`。
- 图表动画默认不超过 `350ms`，数据频繁刷新时禁用进入动画，并遵循 `prefers-reduced-motion`。

### 4.4 响应式图表

- 图表容器必须有确定高度并使用响应式宽度。`< 640px` 减少刻度数量、缩短非关键标签、增大交互目标；不允许只把桌面图等比缩小。
- 移动端优先将横向比较改为横向条形图；无法保持可读性时切换为排序列表或数据表。
- 数据点不得为了适配而被静默删除。若只展示 Top N，标题、摘要或控件必须明确 N 和筛选规则。

## 5. 响应式规则

### 5.1 全局与组件断点

全局断点用于页面壳层和跨页面布局。断点由内容是否失效决定，不代表具体设备：

| 名称 | 范围 | 典型布局行为 |
| --- | --- | --- |
| Base | `< 640px` | 单列、抽屉导航、关键操作优先 |
| `sm` | `>= 640px` | 双列短字段、双列摘要卡 |
| `md` | `>= 768px` | 工具栏横排、表格增加核心列 |
| `lg` | `>= 980px` | 完整侧栏、完整运营表格、双栏面板 |
| `xl` | `>= 1180px` | 三/四列数据卡、增加辅助信息 |
| `2xl` | `>= 1440px` | 限制内容宽度，增加留白而非无限拉伸 |

项目还保留以下已命名、已有测试覆盖的组件内容断点：

| 名称 | 值 | 用途 |
| --- | --- | --- |
| `metric-single-column` | `560px` | 指标条切换为单列 |
| `dense-table-cards` | `760px` | 高密度表格切换为记录卡 |
| `content-stack` | `900px` | 复合内容区和指标条堆叠 |

- 新页面和壳层布局优先使用全局断点及移动优先的 `min-width` 查询。存量 `max-width` 查询不要求机械改写；触达时先确认视觉行为和测试覆盖。
- 组件可以继续使用以上命名内容断点，或改用容器查询。不得新增 720、780、860、1100、1280、1400 等相邻断点，除非组件在现有边界之间发生可复现的内容破坏。
- 新增组件断点时必须命名、说明触发条件并补充响应式测试。CSS 自定义属性不能直接作为媒体查询条件；断点值在文档和测试常量中保持一致。

### 5.2 布局、密度与导航

- 页面水平内边距：Base `16px`，`md` 起 `24px`，`2xl` 起内容区域设最大宽度并居中。页面主要区块间距默认 `20–24px`。
- 使用 Grid/Flex 的流式宽度和 `minmax()`；子项必须设置允许收缩，避免长 IMSI、英文标签或单位撑破布局。
- 先按优先级重排，再考虑隐藏。主任务、当前状态、错误和主要操作不得因窄屏消失；辅助说明可以折叠到详情。
- `lg` 以下侧栏转为抽屉或紧凑导航，打开时管理焦点、锁定背景滚动，并支持 Escape 关闭。
- 页面不得出现由布局造成的整体横向滚动；只有表格、代码、时间轴等明确的局部容器可以横向滚动。

### 5.3 输入方式、文字与媒体

- 不依赖 hover 暴露必要信息或操作。鼠标有 hover，键盘有 `focus-visible`，触控有持久入口。
- `pointer: coarse` 时所有交互目标至少 `44 × 44px`，相邻目标至少留 `8px`；桌面紧凑模式也必须保留清晰焦点和可点击区域。
- 正文最小 `14px/20px`，输入框在移动端至少 `16px` 以避免浏览器自动缩放。标题可以使用 `clamp()`，但层级和行高必须稳定。
- 中英文都要测试：容器不得依赖固定文本宽度；按钮可换行但不截断动作词；长标识符允许在安全位置断行或提供局部滚动。
- 图片提供与显示尺寸匹配的响应式资源；数据图和图标不因高像素密度模糊。

## 6. 合并前检查清单

每项 UI 变更至少验证：

- [ ] 新视觉值来自 token；浅色和深色主题均正常。

## 7. 当前项目的渐进迁移优先级

1. **P0：无障碍和正确性**：为表单补齐 `htmlFor/id/aria-describedby/aria-invalid`；为排序表头补齐按钮与 `aria-sort`；为图表补文本摘要。

4. **P3：体验增强**：提供图表数据表、表格列优先级控制和长表单未保存保护。
